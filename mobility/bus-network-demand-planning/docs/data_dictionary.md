# Data dictionary

All tables are synthetic and generated by `src/bus_network/world.py` with a fixed seed. City
coordinates and populations are public geography. Partner companies are invented and carry
"(fictional)" in their names. There is no passenger-level data anywhere in the project: bookings
are counts per trip.

The trip id joins ticketing and operations: `L010A-20260301-0800` is line L010, direction A,
1 March 2026, departure 08:00.

## stops (planning tool)

| Column | Meaning |
|---|---|
| stop_id | S01 to S32, plus S99 (a planted duplicate) |
| city, stop_name, country | Stop description |
| lat, lon | WGS84 coordinates. One stop has them swapped on purpose |

## line_stops (planning tool)

The ordered stops of each line, direction A. Direction B runs the same stops in reverse.

| Column | Meaning |
|---|---|
| line, seq | Line id and stop order |
| stop_id, city | Stop served |

## timetable (planning tool)

One row per line, direction and departure time.

| Column | Meaning |
|---|---|
| line, direction, dep_time | Departure |
| bus_type_planned | single (49 seats) or double (79 seats); this is what ticketing sells |
| partner_id | Bus partner that runs the departure |
| origin, destination | First and last city |

## partners (partner CRM)

| Column | Meaning |
|---|---|
| partner_id, partner_name | P01 to P09, all fictional |
| home_depot | City of the depot |
| contract_status, contract_end | Contract state and end date |
| fleet_single, fleet_double | Buses the partner owns by type |
| account_owner | Team role responsible, not a person |

## operations (operations log)

One row per departure that the partner reported.

| Column | Meaning |
|---|---|
| trip_id, date, line, direction, dep_time, partner_id | Departure |
| bus_type, seats | Bus that actually ran |
| status | operated or cancelled |
| delay_min | Arrival delay at the final stop |

## bookings (ticketing)

One row per trip with tickets sold.

| Column | Meaning |
|---|---|
| trip_id | Trip |
| pax | Passengers booked on the trip |
| pax_km | Sum of passenger-km |
| peak_load | Passengers on board on the busiest segment |
| peak_segment | That segment, e.g. Cologne-Duesseldorf |
| revenue_eur | Ticket revenue |
| sold_out | True when demand on the busiest segment reached the seats sold |

## od_monthly (ticketing)

Passengers and revenue per month, line and origin-destination pair. Used for the gravity model and
reconciled against trip bookings in check V08.

## truth_demand (simulation only)

The demand that would have booked if seats were unlimited. A real operator never sees this table.
It exists here so the forecast can be scored against true demand, not only against capped bookings.

| Column | Meaning |
|---|---|
| unconstrained_pax | Passengers who wanted to travel |
| unconstrained_peak | Passengers who wanted the busiest segment |
